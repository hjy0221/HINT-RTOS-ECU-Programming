# RTOS_ISR_QUEUE_DEMO

FreeRTOS 큐를 사용하는 생산자·소비자와 외부 인터럽트 실습입니다. 기존 폴더·솔루션 이름의 `ISR` 뒤 공백은 유지합니다. 강의 PDF 원본은 포함하지 않습니다.

## 실행과 연결

[솔루션](RTOS_ISR%20_QUEUE_DEMO/RTOS_ISR%20_QUEUE_DEMO.atsln)을 Microchip Studio에서 열고 빌드합니다. ATmega128, 14.7456 MHz, AVR-GCC `-Os` 설정을 사용합니다.

| 기능 | 연결 |
| --- | --- |
| LED | PB0~PB7, Active Low |
| LCD 데이터 | PA0~PA7 |
| LCD 제어 | PG0=RS, PG1=RW, PG2=E |
| SW2 | PE4/INT4와 GND 사이, 내부 풀업 사용 |

## 동작

| 태스크 | 개수 | 우선순위 | 역할 |
| --- | --- | --- | --- |
| Producer | 5 | 1 | 1~3초 대기 후 큐에 1바이트 저장 |
| Consumer | 5 | 1 | 3~6초 대기 후 큐에서 1바이트 수신 |
| Clear | 1 | 2 | 인터럽트 신호를 받으면 큐 초기화 |
| LCD | 1 | 1 | 약 200 ms마다 큐 개수 표시 |

큐 용량은 8개입니다. 생산자가 더 빠르므로 큐가 차는 모습을 관찰할 수 있습니다. 큐가 가득 차면 생산자는 `xQueueSend()`, 비어 있으면 소비자는 `xQueueReceive()`에서 대기합니다. 소비한 값은 사용하지 않습니다.

LCD 첫 줄은 `Queue Count:`, 둘째 줄은 `Count = 숫자`입니다. 숫자는 현재 저장된 항목 수인 0~8이며, 생산자 수 5와는 별개입니다. LED도 항목 수만큼 켜집니다.

## SW2와 ISR

1. SW2를 누르면 PE4가 High에서 Low로 바뀌어 INT4 인터럽트가 발생합니다.
2. `ISR(INT4_vect)`는 `xSemaphoreGiveFromISR()`로 이진 세마포어에 신호를 보냅니다.
3. Clear 태스크가 깨어나 `xQueueReset()`으로 큐 내용을 비웁니다. 큐 객체 자체를 삭제하는 것은 아닙니다.
4. 생산자와 소비자는 계속 실행하므로 초기화 직후에도 데이터가 다시 들어올 수 있습니다.

현재 AVR 포트는 `portYIELD_FROM_ISR`를 제공하지 않아 다음 틱에서 Clear 태스크로 전환합니다. ISR 안에서는 LCD 출력이나 큐 초기화를 하지 않습니다.

버튼 채터링 제거는 강의 예제와 같이 구현하지 않았습니다. 한 번 눌러 여러 에지가 발생하면 여러 번 초기화될 수 있고, 이진 세마포어에 이미 신호가 있으면 추가 신호는 합쳐집니다. LCD 갱신 전에 생산이 재개되면 화면에서 0이 보이지 않을 수도 있습니다.

## 구현 보완

강의 예제의 큐 크기, 태스크 수, 대기 시간, 우선순위와 INT4 방식을 유지했습니다. 스택 여유를 위해 각 애플리케이션 태스크는 160바이트, 힙은 3,000바이트로 설정했습니다. LED 갱신은 짧은 임계 구역으로 감싸 큐 개수 읽기와 PORTB 출력 사이의 태스크 전환을 막았습니다. 세마포어 수신 성공 여부도 검사합니다.

태스크 또는 큐·세마포어 생성에 실패하면 LED 전체를 켜고 정지합니다. 정상적으로 큐가 가득 찬 경우에도 모든 LED가 켜지므로 LED만으로 오류를 판별할 수 없습니다.

## 검증

AVR-GCC 컴파일·링크는 경고 없이 통과했고 ELF와 HEX를 생성했습니다. text 7,206바이트, data 94바이트, bss 3,111바이트이며 정적 SRAM 사용량은 힙을 포함해 3,205바이트입니다.

AVRISP mkII로 ATmega128 연결을 확인하고 기존 Flash를 백업한 뒤 새 HEX를 기록했습니다. 기록 후 Verify가 통과했습니다.

LCD·LED 변화와 SW2 초기화의 실제 관찰, 장시간 실행 및 스택 여유는 별도 확인이 필요합니다.
