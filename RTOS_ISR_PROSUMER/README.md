# RTOS_ISR_PROSUMER
생산자 5개와 소비자 5개가 8칸 원형 버퍼를 공유하고, 짧은 임계 구역으로 동시 접근을 보호하는 FreeRTOS 실습입니다. LED와 LCD에는 현재 버퍼의 데이터 개수를 표시합니다.

[전체 실습 목록](../README.md) · [main.c](RTOS_ISR_PROSUMER/RTOS_ISR_PROSUMER/main.c) · [FreeRTOSConfig.h](Source/include/FreeRTOSConfig.h)

## 실행 방법

1. [RTOS_ISR_PROSUMER.atsln](RTOS_ISR_PROSUMER/RTOS_ISR_PROSUMER.atsln)을 Microchip Studio에서 엽니다.
2. ATmega128, `F_CPU=14745600UL` 설정을 확인하고 빌드합니다.
3. 프로젝트의 `Debug` 폴더에 생성된 `.hex` 또는 `.elf`를 보드에 기록합니다.

Debug와 Release 모두 크기 최적화 `-Os`를 사용합니다. LED는 PB0~PB7, LCD는 PA0~PA7과 PG0=RS, PG1=RW, PG2=E에 연결합니다. LED는 Active Low가 기본이며 반대 극성의 보드는 `main.c`의 `LED_ACTIVE_LOW`를 0으로 바꿉니다.

## 화면과 태스크

LCD 첫 줄은 `Buffer Count:`, 둘째 줄은 `Count = 0`부터 `Count = 8`까지 표시합니다. LED는 저장된 데이터 개수만큼 켜집니다.

| 태스크 | 개수 | 대기 간격 | 수행 내용 |
| --- | --- | --- | --- |
| `vProducerTask` | 5 | 2~4초 | 공간이 있으면 데이터 저장 |
| `vConsumerTask` | 5 | 2~4초 | 데이터가 있으면 가장 오래된 값 읽기 |
| `vLCDTask` | 1 | 약 200 ms | 현재 데이터 개수 표시 |

애플리케이션 태스크 11개는 모두 우선순위 1입니다. FreeRTOS는 별도로 Idle 태스크를 생성합니다.

버퍼가 가득 차면 생산 시도를, 비어 있으면 소비 시도를 건너뜁니다. 다음 시도 전에는 다시 2~4초를 기다립니다. 소비한 값은 이번 실습에서는 사용하지 않습니다. 대기 시간의 의사난수 시드는 고정되어 있어 재시작하면 같은 수열을 사용합니다.

## 공유 버퍼 보호

| 변수 | 의미 |
| --- | --- |
| `buffer[8]` | 데이터를 저장하는 원형 버퍼 |
| `head` | 다음 저장 위치 |
| `tail` | 다음 읽기 위치 |
| `count` | 현재 저장된 개수, 0~8 |

생산자와 소비자는 다음 작업 전체를 `taskENTER_CRITICAL()`과 `taskEXIT_CRITICAL()` 사이에서 수행합니다.

1. 버퍼에 공간 또는 데이터가 있는지 검사합니다.
2. 데이터를 저장하거나 읽습니다.
3. 인덱스와 개수를 갱신하고 LED를 변경합니다.

이 AVR 포트는 진입 시 SREG를 보관하고 인터럽트를 차단한 뒤, 종료 시 이전 SREG를 복구합니다. `volatile`만으로는 여러 명령으로 이루어진 갱신을 보호할 수 없으므로 임계 구역이 필요합니다. 이 구간에는 대기나 태스크 전환을 유발하는 API가 없습니다.

LCD 태스크는 임계 구역에서 `count`만 복사하고 출력은 밖에서 수행합니다. 실행 중 LCD를 쓰는 태스크는 하나이며, 화면 갱신 주기 때문에 LED와 LCD가 순간적으로 다른 개수를 표시할 수 있습니다.

이름에 ISR이 있지만 별도의 `ISR(...)` 핸들러를 작성하는 예제는 아닙니다. 태스크 사이의 공유 데이터 보호에 인터럽트 차단을 사용합니다.

## 메모리와 오류 처리

| 설정 | 값 |
| --- | --- |
| 애플리케이션 태스크별 스택 | 128바이트 |
| FreeRTOS 힙 | 2,800바이트 |
| 틱 주파수 설정 | 1,000 Hz |
| 메모리 할당 구현 | `heap_1.c` |

태스크 생성 또는 스케줄러 시작 실패 시 `stop_on_error()`가 LED 전체를 켜고 정지합니다. 버퍼가 가득 찬 경우에도 LED 전체가 켜지므로 LED만으로 오류를 구분할 수는 없습니다.

## 강의 예제와 차이

`10. RTOS_ISR_PROSUMER.pptx`의 4~15번 슬라이드를 기준으로 작성했습니다. 강의자료 원본은 저장소에 포함하지 않습니다.

| 항목 | 구현 |
| --- | --- |
| 기본 동작 | 생산자·소비자 각각 5개, 버퍼 8칸, 2~4초 대기 유지 |
| 난수 함수 | 실제 사용하는 2~4초 범위를 반환하는 함수로 통합 |
| 태스크 스택 | 슬라이드의 80바이트에서 128바이트로 조정 |
| 힙 | 기존 프로젝트 설정 1,500바이트에서 2,800바이트로 확대 |
| 태스크 이름 | 이름 길이 설정에 맞게 `Prod`, `Cons`, `LCD` 사용 |
| 실패 처리 | `stop_on_error()`로 통합 |

마지막 슬라이드의 `RTOS_ISR_INTERLEAVED_LCD`는 별도 추가 과제이며 이 프로젝트에는 포함하지 않았습니다. LCD처럼 긴 작업 전체를 임계 구역에 넣으면 틱 처리가 지연됩니다. 임계 구역 안에서 `vTaskDelay()`를 호출해서도 안 됩니다.

## 검증 상태

AVR-GCC로 커널, AVR 포트, LCD 드라이버와 `main.c`를 컴파일·링크하여 경고 없이 `.elf`와 `.hex`를 생성했습니다.

| 구분 | 크기 |
| --- | --- |
| text | 4,860바이트 |
| data | 62바이트 |
| bss | 2,918바이트 |
| 정적 SRAM 사용량 (data + bss) | 2,980바이트 |

정적 SRAM 사용량에는 FreeRTOS 힙이 포함됩니다. 실제 보드 실행, LCD 표시, 장시간 태스크 스택 사용량은 아직 검증하지 않았습니다.
