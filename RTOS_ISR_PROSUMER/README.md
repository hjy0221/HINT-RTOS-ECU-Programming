# RTOS_ISR_PROSUMER 실습

`10. RTOS_ISR_PROSUMER.pptx`의 4~15번 슬라이드에 나온 생산자·소비자 예제를 구현합니다. 강의자료 원본은 포함하지 않습니다.

## 실행

`RTOS_ISR_PROSUMER/RTOS_ISR_PROSUMER.atsln`을 Microchip Studio에서 열고 빌드합니다. 대상은 ATmega128, 클럭은 14.7456 MHz입니다. Debug와 Release 모두 크기 최적화 `-Os`를 사용합니다.

LED는 PB0~PB7에 연결하며 기본 설정은 Active Low입니다. LCD 데이터는 PA0~PA7, 제어는 PG0=RS, PG1=RW, PG2=E를 사용합니다. LED가 반대로 표시되는 보드라면 `main.c`의 `LED_ACTIVE_LOW`를 0으로 바꿉니다.

## 동작 순서

1. LED와 LCD를 초기화하고 첫 줄에 `Buffer Count:`를 표시합니다.
2. 생산자 5개, 소비자 5개, LCD 태스크 1개를 우선순위 1로 생성합니다.
3. 생산자는 태스크별 의사난수로 2~4초 대기한 후 빈 공간이 있으면 8칸 원형 버퍼에 값을 넣습니다.
4. 소비자는 2~4초 대기한 후 데이터가 있으면 가장 먼저 들어온 값을 꺼냅니다. 꺼낸 값은 이번 실습에서는 사용하지 않습니다.
5. LED는 버퍼에 들어 있는 데이터 개수만큼 켜집니다. LCD 둘째 줄은 약 200 ms마다 `Count = 0`부터 `Count = 8`까지 표시합니다.

버퍼가 가득 차면 생산 시도를 건너뛰고, 비어 있으면 소비 시도를 건너뜁니다. 조건이 바뀔 때까지 세마포어나 큐에서 대기하는 구조는 아닙니다. 난수 시드는 고정되어 있으므로 재시작하면 같은 수열을 사용합니다.

## 임계 구역

`head`는 다음 저장 위치, `tail`은 다음 읽기 위치, `count`는 현재 데이터 개수입니다. 조건 검사부터 버퍼 접근, 인덱스와 개수 변경, LED 갱신까지 `taskENTER_CRITICAL()`과 `taskEXIT_CRITICAL()` 사이에서 수행합니다.

이 프로젝트의 AVR 포트는 진입 시 SREG를 보관하고 인터럽트를 차단한 뒤, 종료 시 이전 SREG를 복구합니다. 이 짧은 구간에는 대기나 태스크 전환을 유발하는 API가 없습니다. `volatile`만으로는 여러 명령으로 이루어진 갱신을 보호할 수 없으므로 임계 구역이 필요합니다.

LCD 태스크는 임계 구역에서 `count`만 복사하고 실제 LCD 출력은 밖에서 수행합니다. LCD 접근은 이 태스크만 담당하므로 태스크 사이의 LCD 출력 충돌을 피합니다. 화면은 주기적으로 갱신되므로 LED와 순간적으로 다른 개수를 표시할 수 있습니다.

프로젝트 이름에 ISR이 있지만 별도의 `ISR(...)` 핸들러를 작성하는 실습은 아닙니다. 태스크 사이의 공유 데이터 보호에 인터럽트 차단을 사용하는 예제입니다.

## 강의 예제와 구현 차이

- 생산자·소비자 각각 5개, 버퍼 크기 8, 대기 2~4초와 LCD 200 ms 주기는 유지했습니다.
- 난수 함수는 실제 사용하는 2~4초 범위를 반환하도록 하나로 정리했습니다.
- 슬라이드의 태스크 스택 80 대신 128바이트를 사용하고, 복사한 설정의 힙 1,500바이트를 2,800바이트로 늘렸습니다. Idle 태스크도 같은 힙에서 생성됩니다.
- 태스크 이름은 기존 이름 길이 설정에 맞춰 `Prod`, `Cons`, `LCD`로 줄였습니다.
- 태스크 생성 또는 스케줄러 시작 실패 시 LED 전체를 켜고 정지하는 처리를 `stop_on_error()`로 모았습니다.

마지막 슬라이드의 `RTOS_ISR_INTERLEAVED_LCD`는 별도 추가 과제이므로 이 프로젝트에 포함하지 않았습니다. LCD 출력처럼 긴 작업 전체를 인터럽트 차단으로 감싸면 틱 처리가 지연됩니다. 임계 구역 안에서 `vTaskDelay()`처럼 태스크를 대기시키는 API를 호출해서도 안 됩니다.

## 확인 결과

설치된 AVR-GCC로 커널, AVR 포트, LCD 드라이버와 `main.c`를 함께 컴파일·링크했으며 경고 없이 `.elf`와 `.hex`를 생성했습니다. 크기는 text 4,860바이트, data 62바이트, bss 2,918바이트입니다. 정적 SRAM 사용량은 data+bss인 2,980바이트이며 FreeRTOS 힙을 포함합니다.

실제 보드 실행, LCD 표시, 장시간 태스크 스택 사용량은 아직 검증하지 않았습니다.
